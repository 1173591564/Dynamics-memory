# 调查员：统一因果上下文与预算

> 状态：现行 · 调查员因果上下文与预算的基础契约（第二批）。

工具循环与调查员仅在 `MEMORY_PIPELINE=legacy` 下运行；默认三 Agent 管线不使用
`open_budget` 工具预算，但 `InvestigationContext` 因果上下文类型为两条管线共用
（recall/feedback 的准入同源）。配套测试：`tests/test_investigation_scope.py`。
本页记录第二批边界契约。后续 [第三批](durable-tasks.md) 已实现调查任务、产物、
回执和每日次数持久化，以及同任务规范化操作的幂等重放；未关联持久任务的调用仍按本页
基础契约运行。工具预算按每次调查尝试开关，不是跨尝试累计。仍未进行 L3 验证。

## 1. 一个调查上下文、一份工具预算

`open_budget()` 返回不可变 `InvestigationContext(signal_id, before, origin)`。
进程内调查员直接向服务方法传 `signal_id`，六个只读工具共用这个准入边界。
HTTP 兼容接口仍可用 `X-Signal-Id` 查找活跃调查，不能传入这个 Python 对象；主 agent 插件不再充当 worker。

所有调查工具共用一次准入操作 `_admit()`，在同一个服务锁临界区中：

1. 校验信号存在且未关闭；不存在、已关闭或空白信号号返回 **403**。
2. 计工具调用尝试次数；超过 `tool_calls` 返回 **429**。
3. 固定本次请求的因果上界与来源标签。
4. 对 `log_window` 同时预留原文额度，再释放锁执行 I/O。

准入后不再用 signal_id 二次查找上界。请求中的日志/propose `before` 只能
缩紧，不能放宽调查的 `before`。默认调查上界为 `sig.t + 1`，因此包含信号所在步。
`open_budget()` 要求有限的非负整数上界、非负预算；不能覆盖仍活跃的同名预算。

| 端点 | 调查调用行为 |
|---|---|
| `/log/search`、`/log/timeline`、`/log/stats` | 统一计次；所有子查询使用同一个固定上界 |
| `/log/window` | 统一计次；同时受累计原文字数预算和固定上界限制 |
| `/search`、GET `/recall` | 统一计次；在因果筛选后的记忆副本中检索 |
| GET `/conflicts` | 统一计次；只返回界内双方及界内最后观测的 tension |
| `/resolve` | 统一计次；裁决前校验双方及其替代/聚合链，不允许用旧 ID 跳到未来代表 |
| `/propose` | 统一计次；来源与 supersedes 校验在入库前完成，origin 使用调查上下文 |
| `/diagnose` | 统一计次；失效调查不能继续修改诊断统计 |

带信号的请求不能调用 `/observe`、`/feedback`、`/miss`、`/save` 或 `/signals`，
这些是主回路/管理接口，返回 403。`/health` 仍是公开、无原文、不计次的启动探针，
保留插件初始化兼容性。

没有 `X-Signal-Id` 的主 agent 请求保持原来的通路和反馈登记语义。
**这不是按身份区分的 HTTP 授权系统**：持有服务 token 的客户端可以省略信号头。
默认调查员不持有 HTTP 工具通道，只执行进程内六个只读工具，写回由 AgentWorker 接管。

## 2. 并发回展先预留、后结算

每份预算记录：

- `window_used`：已成功读取并准备返回的 user_text + assistant_text 字符数；
- `window_reserved`：尚在执行的回展请求预留量；
- 可用额度：`window_chars - window_used - window_reserved`。

同一临界区内按剩余额度与请求 `max_chars` 的较小值预留。另一个并发请求
不能再次使用这笔余额；没有余额时立即返回 429，不等待慢 I/O。

读取成功只结算实际字符，退还未用部分；读取异常退还整笔预留，但调用次数不退。
字数按 Python 字符计，不是字节或 token；不包含元数据，也不计其他工具的片段输出。

`close_budget()` 阻止新的准入，不强制中断已准入的读取。已经准入的请求可以完成，
但仍受原上界和预留量限制。结算直接使用原预算对象，即使进程内管理代码重新打开
同名预算，也不会把旧请求的字数记到新调查。关闭时返回的 usage 包含当时尚未结算的
`window_reserved`，是关闭时刻快照，不是等待全部网络响应完成后的统计。

`calls` 沿用“尝试次数”口径，包含因次数/字符额度不足而被拒绝的调用，所以可能大于
`tool_calls`；真正获准的调用不会超上限。HTTP 参数格式校验失败的 400 不计次数。
预算不是速率限制，也不代表 LLM 请求数或费用上限。

## 3. 查记忆不是回放历史引擎

不能只按 `birth` 过滤：旧条目可能已经在之后被重新确认或合并了新来源。
当前保守策略要求：

- `birth < before` 且 `last_seen < before`；
- 所有已有 `src` 都存在于 L0，且对应日志 `t < before`；
- 替代/聚合指针涉及的条目也须通过同样的检查，不能绕过时间边界。

先筛选，再执行原来的排序、质量门和压制逻辑；不是取完 top-k 再删除未来条目。
冲突附带文本也只能来自这个筛选后的集合。查询运行在记忆/张力副本上，关闭信用
发放，不影响主引擎的复活、计数、信号或检索登记；返回 `retrieval_id: null`。

这不是历史版本存储：不会恢复过去的文字版本、排名、置信度或生命周期状态。
后来的修改可能让一条旧记忆被保守排除，调查中刚写入但 birth 已超过上界的修复记忆
也可能被排除；仍可通过 L0 找证据。旧记忆的空 src 不在本批强制补齐，新的 proposal
继续要求非空来源。这里不承诺完整的历史无前窥评测语义。

## 4. 写回与最终 JSON 分开处理

普通 HTTP `/propose`、`/resolve`、`/diagnose` 都必须经过活跃调查准入，消耗工具次数。
来源标签不信任请求体；越界 supersedes 会拒绝整个对应 proposal，不先创建半条记忆；
越界 resolve 在建 tension、写 entity_key、结算信用前就拒绝。

调查员结束后，`AgentWorker` 先关闭工具预算，再用开预算时保留的 Python 上下文提交
正常最终 JSON。这个进程内路径：

- 不重新打开旧 signal_id；超时/关闭后迟到的 HTTP 工具仍被拒绝；
- 不额外消耗工具次数，所以额度耗尽后仍能汇总输出；
- 保留原 before/origin，proposal 和 verdict 仍做因果校验；
- 单条越界 verdict 拒绝并记录告警，不阻断同份结果中的合法诊断/其他条目。

每次调查尝试的信号句柄增加随机后缀，重试或重启后即使队列编号重复，旧句柄也不能
借用新一轮的预算。内部 `_context` 参数不从 HTTP 请求体读取。

提议通过后仍使用当前主引擎的同一条 ingest/dedup 回路，不另建特权池或历史引擎。
**后续更新**：第三批为持久调查任务加入了操作回执，支持常见工具提交/最终 JSON
规范化操作去重、保存产物的持久重试、租约恢复及日限额持久化。每次尝试的工具预算
不跨重启保存；证据实际看过/蕴含校验、整份结果事务和非调查语义队列恢复仍未实现。
精确适用范围与失败行为见 [任务恢复说明](durable-tasks.md)。
